# Day 3 Quiz: Answers

1. BFS: unweighted shortest path (fewest edges). Dijkstra: non-negative weights. 0-1 BFS: weights 0/1 (a deque: 0-edges push to the front). Bellman-Ford: negative weights or negative-cycle detection, O(VE).
2. Otherwise the same node gets pushed many times before its first pop → duplicate work, potentially exponential queue growth on grids, and TLE.
3. BFS/DFS 2-coloring; fail when an edge connects two same-colored nodes (an odd cycle). Trap: a **disconnected** graph, so start a BFS from every uncolored node.
4. In a DAG, a node can be reached via two different paths (a diamond), and "already visited" doesn't mean it's on the current path. Use 3 colors (white/gray/black): only an edge to a **gray** (on the recursion stack) node is a cycle. Or use Kahn.
5. If the number of output nodes < n, a cycle exists (those nodes never reach indegree 0). Levelization: when popping u, set `level[v] = max(level[v], level[u]+1)` for each successor.
6. Path compression (or halving) + union by rank/size → amortized O(α(n)), effectively constant.
7. Detecting and **reporting combinational loops** (SCCs of size > 1, or self-loops) before timing/levelization. Also: finding strongly coupled logic for clustering, and sequential-loop analysis in formal.
8. (1) State definition in words, (2) transition (the last choice), (3) base cases, (4) evaluation order, (5) where the answer lives. **Step 1** (an ill-defined state) causes most bugs.
9. Coins outer / amount inner → **combinations** (each multiset once). Amount outer / coins inner → **permutations** (ordered sequences counted separately).
10. Descending ensures `dp[cap − w]` still holds the value from *before* this item was considered, so each item is used at most once. Ascending would allow reuse (unbounded knapsack).
11. `tails[k]` = the smallest possible tail value of an increasing subsequence of length k+1. It's sorted because a longer increasing subsequence must end with a larger value than the smallest tail of a shorter one. So binary search (`lower_bound`) finds where x extends or improves.
12. `dp[i][j]` = edits to turn `a[0..i)` into `b[0..j)`. If `a[i-1]==b[j-1]`: `dp[i-1][j-1]`; else `1 + min(dp[i-1][j-1] replace, dp[i-1][j] delete, dp[i][j-1] insert)`. Base: `dp[i][0]=i`, `dp[0][j]=j`.
13. `x & (x-1)` drops the lowest set bit; `x & -x` isolates it; `x && !(x & (x-1))` is a power of two; `(x >> k) & 1` tests; `x | (1<<k)` sets; `x & ~(1<<k)` clears; `x ^ (1<<k)` toggles; `__builtin_popcount`.
14. Forward: `AT[v] = max over preds (AT[u] + d(u,v))`. Backward: `RT[u] = min over succs (RT[v] − d(u,v))`. Slack = RT − AT. WNS = the most negative slack among the endpoints (the worst violation).
15. Positive skew (the capture clock arrives later) **helps setup** (more time) and **hurts hold** (data must stay stable longer after the later capture edge).
16. Forward: the arrival times in the arc's **fanout cone** (downstream), processed in level order (bucket queue by level) so each node is recomputed once, stopping early where the value doesn't change. Backward: the required times in the **fanin cone** of the affected endpoints. Slack is re-evaluated where either changed.
17. `cost(n) = (b(n) + h(n)) × p(n)`. b = base cost/delay, p = the present congestion penalty (grows with current overuse and with the iteration count), h = the history cost (accumulates for resources that were overused in past iterations). History makes chronically contested resources permanently expensive, so the nets that have alternatives move away. Without it, nets oscillate between the same congested spots.
18. Move: swap two cells or move one to a nearby site (range-limited). Accept if ΔC < 0, else with probability `e^(−ΔC/T)`; cool T geometrically. ΔHPWL: only the nets incident to the moved cells change; keep per-net bounding boxes (plus counts of pins on each edge) for O(1)-ish updates.
19. **Stack overflow**: 50M-deep recursion exceeds the 8 MB stack. Convert to an iterative DFS with an explicit stack (store {node, next-edge-index} to emulate postorder), or use BFS/Kahn where the order allows. Raising `ulimit -s` / the thread stack size is only a stop-gap.
20. Compute the arrival times and, backward from the endpoints, the "best completion" (the required-time/slack structure). Then run a **best-first search**: a max-heap of partial paths keyed by their best achievable total delay (prefix delay + the longest remaining path to any endpoint). Popping yields complete paths in order, so stop after K. That's O(K·(deg + log)) beyond the linear preprocessing. (Also: deviation-based k-longest paths, as in Eppstein-style methods.)
