    The model in five sentences

    1. The mutex makes "check the condition, then sleep" one indivisible step: nobody can change the queue in between.
    2. cv.wait(lk) releases the lock and sleeps atomically; when woken, it re-acquires the lock before returning.
    3. Being woken is a hint, not a promise: another thread can take the item first (or the wakeup is spurious). So always re-check in a while loop, which wait(lk, pred) does for you.
    4. Change the shared state only while holding the mutex, even if you notify after unlocking. Otherwise a notify can land between a waiter's check and its sleep: a lost wakeup.
    5. A bounded queue needs two condition variables: producers sleep on notFull, consumers on notEmpty, and each side notifies the other.
